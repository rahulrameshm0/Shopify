# Deploying this project on Render

**Live:** https://shopify-b5g9.onrender.com (deployed via the Render CLI)

## Current setup

| Piece | Value |
| --- | --- |
| Service | `shopify` (`srv-dbr1ka3m8hqs73ca1a9g`), Python, free plan, Oregon |
| Repo / branch | `rahulrameshm0/Shopify` / `main` (auto-deploy on push) |
| Build | `./build.sh` → install deps, `collectstatic`, `migrate`, seed catalogue |
| Start | `./start.sh` → `migrate`, seed, create admin, Gunicorn on `$PORT` |
| Static | WhiteNoise (`CompressedStaticFilesStorage`) |
| Database | **SQLite** at `/opt/render/project/src/db.sqlite3` |
| Media | Served from `media/`; uploads are ephemeral |

### Why SQLite?

Render allows **one active free Postgres per workspace**, and that slot is used
by the live `shelf` app (`shelf-db`). A Postgres upgrade (~$6/month) is the
recommended next step; switching is a single env var change:

```
DATABASE_URL=<postgres connection string>
```

Everything else (migrations, seeding, queries) is already database-agnostic.

> SQLite lives on the service filesystem, which is rebuilt on every deploy, so
> orders/users registered on the site are lost when you redeploy. The product
> catalogue is restored automatically from `core/fixtures/catalog.json`.

## Admin login

`/admin/` is enabled. Credentials are created from these service env vars by
`python manage.py ensure_superuser` on every boot:

- `DJANGO_SUPERUSER_USERNAME`
- `DJANGO_SUPERUSER_EMAIL`
- `DJANGO_SUPERUSER_PASSWORD`

Set/rotate them in the Render dashboard (**Environment**). Deleting the
username/password vars disables the boot-time creation.

## Environment variables

| Key | Value |
| --- | --- |
| `DEBUG` | `False` |
| `SECRET_KEY` | generated by Render |
| `DJANGO_ALLOWED_HOSTS` | `.onrender.com` |
| `CSRF_TRUSTED_ORIGINS` | `https://*.onrender.com` |
| `DATABASE_URL` | `sqlite:////opt/render/project/src/db.sqlite3` |
| `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` | set in dashboard (checkout needs them) |
| `EMAIL_HOST_USER` / `EMAIL_HOST_PASSWORD` | set in dashboard (account emails) |

`RENDER_EXTERNAL_HOSTNAME` and `RENDER_EXTERNAL_URL` are injected by Render and
added to `ALLOWED_HOSTS` / `CSRF_TRUSTED_ORIGINS` automatically.

## Redeploying

Push to `main` — Render builds and deploys automatically. Manual deploy:

```bash
render deploys create srv-dbr1ka3m8hqs73ca1a9g
render logs --resources srv-dbr1ka3m8hqs73ca1a9g
```

## Custom domain

Add the domain in Render, then extend the env vars:

```
DJANGO_ALLOWED_HOSTS=.onrender.com,yourdomain.com
CSRF_TRUSTED_ORIGINS=https://*.onrender.com,https://yourdomain.com
```

## Local development

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_catalog   # optional demo data
python manage.py runserver
```

The original `.env` + Docker flow (`docker compose up`) still works and uses
Postgres from `DB_*` variables.
